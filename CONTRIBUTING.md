# Contributing to Airi-PC\n\nThanks for helping improve Airi-PC. The goal is to keep the public project reproducible, understandable and honest about what has actually been verified.\n\n## Before opening an issue\n\nCheck the [Troubleshooting Guide](docs/TROUBLESHOOTING.md) first.\n\nFor bugs, include a reproducible description and safe diagnostic output. Do not attach credentials, cookies, tokens, private keys or private runtime state.\n\n## Pull requests\n\nPrefer focused changes. A good PR should explain:\n\n- what changed;\n- why it changed;\n- how it was tested;\n- any known limitations.\n\n## Verification\n\nUse the checks relevant to your change. For core Python/runtime changes, the canonical project checks include:\n\n```sh\npython3 -m compileall -q computer api scripts tests airi-pc-companion\npython3 -m pytest -q\npython3 scripts/airi-rebuild-verify.py\n./scripts/airi-runtime-verify\n```\n\nFor Windows Companion changes, also run the Companion test suite and verify the Windows packaging workflow when practical.\n\n## Documentation accuracy\n\nDo not add claims such as `production ready`, `fully autonomous` or `secure` unless the repository contains evidence that supports the claim. Keep user-facing documentation aligned with the implementation and tests.\n\n## Security\n\nNever commit secrets or local runtime state. Read [SECURITY.md](SECURITY.md) before making changes that affect authentication, remote MCP or transport.\n
